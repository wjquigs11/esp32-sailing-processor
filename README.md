# ESP32 Sailing Processor

I have been sailing since I was a kid. Mostly on cheap beater boats. The first boat I purchased on my own was an early 1980s Catalina 22 with a swing keel. Most of the boats I've owned haven't had any serious instrumentation except for, usually, a depth sounder. I wasn't opposed to it; I just didn't want to spend the money.
Then I participated in the 2019 Race to Alaska, and changed my mind. Sailing upwind, in light and shifty breeze, in the middle of the night, is challenging. Having *some* idea where the wind is coming from is incredibly useful. So after that race, I bought an entry-level instrument package, and had a wind transducer for the first time since I launched my boat in 2006. There was an immediate problem. My boat is a trimaran, and it has a rotating mast, which improves the aerodynamics of the main sail, by a lot. But only a tiny fraction of boats have rotating masts, so wind transducers are built for all the other boats with fixed masts. As soon as the mast rotates away from the centerline of the boat, the wind direction reading from the masthead instrument is invalid.
A very clever guy named Randel came up with a simple solution: he mounted a Honeywell rotation sensor at the base of the mast, and used an ESP32 microcontroller (MCU) to calculate the angle of the mast, which he then added or subtracted from the reading from the masthead transducer to get a corrected reading, which he transmitted on the boat network. After some trepidation, I taught myself a bit of microcontroller coding and copied his system, but immediately ran into another problem. My instruments are manufactured by Garmin, and Garmin instruments basically assume that everything in the world is Garmin. If you have a Garmin mast transducer transmitting an "incorrect" wind angle reading, and a non-Garmin instrument transmitting a correct wind angle reading, there's no way to convince your Garmin display to ignore the incorrect reading.
There happens to be a very basic solution to this problem that's been around as long as Ethernet: a bridged network. My boat has two NMEA2000 networks. One network connects to the wind transducer, and the other network connects to all the rest of the instruments and displays. The MCU sits between the two; it reads wind data from the wind bus, corrects it for rotation, and transmits it on the other bus. Since the only source of wind information on the main bus is non-Garmin, the Garmin displays have no choice but to use it.
I probably should have stopped there, but I was hooked. There are so many useful applications for a tiny, robust computer with a simple, real-time operating system on a boat. Eventually I added an IMU for heading (which allows me to compute true wind direction, or TWD), a temperature and humidity sensor, an interface to my autopilot so I could steer to a relative wind bearing, an interface to my ICOM VHF radio's GPS sensor, a real-time kinematic (RTK) GPS sensor so I could determine exactly which direction I was pointed (and set and drift of current, leeway, and other useful tidbits). Then I added calculations for true wind speed and angle, a system to point the boat directly into the wind if I happened to fall overboard, a tack sensor... All of this runs on that little computer (which, I estimate, has about the same compute power as my mid-1990s IBM Thinkpad, but draws a fraction of the energy). Also fascinating is that this little gadget costs around $100 in parts and does every single function that you get from a commercial "sailing processor" that costs $10,000. And of course, the code is open source so anyone is free to copy, modify, or just use it as-is.
The only function I deliberately avoided on my sailing processor is chart plotting, because we have SignalK for that, and there's no reason to reinvent that particular wheel. SignalK can also perform many of the calculations that my gadget does either on the MCU itself, or in Javascript on a client like a cell phone. I feel that a bit of redundancy is worthwhile, particularly for home-built systems. I certainly don't claim it's as robust as the $10k commercial version, but I hope that someone finds a bit of utility here.
